# Лабораторна робота №1

## Нейронні мережі для задач класифікації та регресії

У лабораторній роботі досліджується побудова, навчання та порівняння багатошарових перцептронів (MLP) для задач машинного навчання. Експерименти виконані на чотирьох наборах даних і охоплюють:

- бінарну класифікацію на прикладі прогнозування діабету;
- регресію для прогнозування погодинної заробітної плати;
- бінарну класифікацію затримок громадського транспорту;
- багатокласову класифікацію цінового діапазону мобільних телефонів.

Для кожної задачі перевіряється вплив функції активації та оптимізатора на швидкість збіжності й якість моделі. Окремо реалізовано ранню зупинку навчання та порівняння нейронної мережі з класичними алгоритмами машинного навчання.

> **Примітка.** README описує код і результати, збережені у відповідних Jupyter Notebook. Через випадкову ініціалізацію ваг окремий повторний запуск може дати дещо інші значення метрик.

## Загальний підхід

У більшості експериментів використовується однакова схема:

1. завантаження даних за допомогою `pandas`;
2. попередня обробка числових і категоріальних ознак;
3. поділ даних на навчальну, валідаційну та тестову вибірки;
4. стандартизація ознак через `StandardScaler`, причому scaler навчається лише на навчальній вибірці;
5. перетворення даних у тензори PyTorch;
6. навчання MLP протягом максимум 1000 епох;
7. порівняння функцій активації `ReLU`, `Sigmoid` і `Tanh`;
8. порівняння оптимізаторів `SGD`, `RMSprop`, `Adam`, `Adadelta`, `Adagrad`, `Adamax` і `NAdam`;
9. збереження найкращих ваг за валідаційною втратою за допомогою early stopping;
10. оцінювання найкращої моделі на тестовій вибірці.

У реалізації використано повнопакетне навчання: на кожній епосі модель обробляє всю навчальну вибірку одним проходом. Функція втрат і розмір вихідного шару залежать від типу задачі:

- `CrossEntropyLoss` для класифікації;
- `MSELoss` для регресії.

## 1. Бінарна класифікація діабету

### Дані

Файл `diabetes_data.csv` містить 768 спостережень і 8 вхідних ознак:

`pregnancies`, `glucose`, `diastolic`, `triceps`, `insulin`, `bmi`, `dpf`, `age`.

Цільова ознака `diabetes` має два класи:

- `0` — діабет не виявлено;
- `1` — діабет виявлено.

Дані поділено з параметром `random_state=42`: 10% спостережень відкладено для тестування, а частину решти використано для валідації.

### Архітектура MLP

```text
8 ознак → Linear(12) → активація → Linear(8) → активація → Linear(2)
```

Для вибору найкращої конфігурації перебираються 3 функції активації та 7 оптимізаторів. Якість оцінюється за `Accuracy`, `Precision`, `Recall` і `F1-score`.

### Результати

Найкращою конфігурацією за валідаційним `F1-score` у збереженому ноутбуці стала комбінація **Sigmoid + NAdam**:

| Accuracy | Precision | Recall | F1-score |
|---:|---:|---:|---:|
| 0.8170 | 0.8409 | 0.6379 | 0.7255 |

Для порівняння з MLP виконано навчання класичних моделей:

| Модель | Accuracy | F1-score |
|---|---:|---:|
| XGBoost | 0.7647 | 0.6604 |
| Random Forest | 0.7712 | 0.6465 |
| Logistic Regression | 0.7909 | 0.6522 |

Отже, у проведеному експерименті найкраща конфігурація MLP перевершила базові класичні моделі за `F1-score`.

## 2. Регресія погодинної заробітної плати

### Дані

Файл `hourly_wages_data.csv` містить 534 записи. Цільова ознака — `wage_per_hour`. Серед вхідних ознак:

- членство у профспілці (`union`);
- освіта в роках (`education_yrs`);
- досвід роботи (`experience_yrs`);
- вік (`age`);
- стать (`female`);
- сімейний стан (`marr`);
- регіон (`south`);
- галузь виробництва (`manufacturing`, `construction`).

### Архітектура та метрики

Мережа має один вихід для прогнозування числового значення. Для порівняння використовуються:

- `MSE` — середньоквадратична помилка;
- `MAE` — середня абсолютна помилка;
- `R²` — коефіцієнт детермінації.

У ноутбуці найкращий результат серед перевірених конфігурацій MLP отримано для **Sigmoid + Adamax**:

| MSE | R² |
|---:|---:|
| 11.6255 | 0.3172 |

На тестовій вибірці зафіксовано:

| MSE | MAE | R² |
|---:|---:|---:|
| 29.2902 | 3.8734 | 0.2890 |

Порівняння з класичними регресійними моделями на валідації:

| Модель | R² |
|---|---:|
| Linear Regression | 0.1966 |
| Random Forest | -0.1316 |
| XGBoost | -0.4248 |

## 3. Індивідуальне завдання: затримки транспорту

### Дані та підготовка

Файл `public_transport_delays.csv` містить 2000 поїздок. Цільова ознака `delayed` визначає, чи була поїздка затримана:

- `0` — без затримки;
- `1` — затримка.

У ноутбуці виконуються такі кроки:

- пропущені значення `event_type` замінюються на категорію `None`;
- з часу поїздки виділяється числова ознака `hour`;
- технічні поля, станції та часи розкладу вилучаються;
- категоріальні ознаки (`transport_type`, `route_id`, `weather_condition`, `event_type`, `season`) кодуються через one-hot encoding;
- числові ознаки стандартизуються;
- для частково незбалансованих класів використовується зважена `CrossEntropyLoss` з вагами `[3.0, 1.0]`.

Розподіл класів у наборі:

| Клас | Кількість |
|---|---:|
| `delayed = 0` | 501 |
| `delayed = 1` | 1499 |

Модель має ту саму базову структуру, що й класифікатор діабету: два приховані шари з 12 і 8 нейронами та вихідний шар із 2 нейронами. Для коректного вибору моделі порівнюються `Accuracy`, `Precision`, `Recall` і `F1-score`.

## 4. Індивідуальне завдання: класифікація мобільних телефонів

### Дані

Файл `mobile.csv` містить 2000 записів і 20 характеристик мобільних телефонів, зокрема:

- потужність батареї;
- тактову частоту;
- обсяг оперативної та внутрішньої пам’яті;
- роздільну здатність екрана;
- вагу телефона;
- кількість ядер;
- підтримку 3G/4G, Wi-Fi, Bluetooth і dual SIM;
- наявність сенсорного екрана;
- час розмови.

Цільова ознака `price_range` має чотири класи цінового діапазону: `0`, `1`, `2`, `3`. Тому використовується багатокласовий `CrossEntropyLoss`, а для оцінювання — macro-усереднені `Precision`, `Recall` і `F1-score`.

### Архітектура

```text
20 ознак → Linear(64) → активація → Linear(32) → активація → Linear(4)
```

Ноутбук порівнює ті самі 3 функції активації та 7 оптимізаторів, а найкраща модель вибирається за macro `F1-score`. Тестова вибірка формується з `random_state=101`.

## Рання зупинка та аналіз перенавчання

Клас `EarlyStopping` контролює значення валідаційної втрати. Якщо протягом 10 послідовних епох покращення не відбувається, навчання для поточної конфігурації зупиняється. Після цього відновлюються ваги моделі, які відповідали найкращому значенню валідаційної втрати.

У ноутбуках також будуються графіки:

- зміни training loss і validation loss;
- швидкості збіжності різних оптимізаторів;
- порівняння функцій активації;
- ознак перенавчання, коли training loss продовжує зменшуватися, а validation loss зростає.

## Відтворюваність

Для стабільнішого порівняння результатів у коді зафіксовано `random_state` під час поділу даних. Проте в окремих місцях ваги PyTorch ініціалізуються випадково, тому для повної побітової відтворюваності експерименту потрібно додатково зафіксувати seed PyTorch і NumPy перед створенням моделей.

## Висновки

1. Нормалізація ознак є важливою для стабільного навчання MLP, особливо при порівнянні різних оптимізаторів.
2. Якість моделі суттєво залежить від пари «функція активації — оптимізатор»; одна конфігурація не є оптимальною для всіх задач.
3. Рання зупинка дає змогу уникати зайвого навчання після припинення покращення на валідаційній вибірці.
4. Для незбалансованої задачі затримок використання ваг класів у функції втрат допомагає врахувати дисбаланс цільової ознаки.
5. У задачах лабораторної роботи MLP показав конкурентні або кращі результати порівняно з базовими класичними моделями, але якість потрібно оцінювати відповідною метрикою: `F1-score` для класифікації та `MSE`/`R²` для регресії.
